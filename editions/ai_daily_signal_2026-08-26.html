One visit to a webpage is enough: NVIDIA NemoClaw's agent can be hijacked and its model permanently poisoned

Oasis Security disclosed on 25 August a flaw in NVIDIA NemoClaw, tracked as CVE-2026-65105, in which an attacker-controlled webpage takes unauthenticated control of the local Ollama instance serving a developer's AI agent and plants hidden instructions inside the model itself (SiliconANGLE, The Hacker News). The mechanism is old and unglamorous: NemoClaw starts Ollama with OLLAMA_HOST=0.0.0.0:11434, binding the model server to every network interface, and a classic DNS-rebinding technique then lets a visited page reach that API from the browser. From there the researchers rewrote the chat template — the layer that turns any conversation into the text the model actually reads — so that hidden instructions are applied to every later conversation. No stolen credential, no phishing, no user prompt. One page visit.

So what: this is persistence, not a single prompt injection — the payload survives in the model's own template after the tab is closed. If your developers run local agents, audit every model server for a bind address today, and treat "it's only listening on localhost" as a claim to verify rather than a default to trust.

The chain, step by step. NemoClaw launches its local model server with OLLAMA_HOST=0.0.0.0:11434. That binds Ollama to every interface on the machine rather than the loopback, and Ollama's API requires no authentication. A page the developer visits cannot normally talk to that port because of the browser's same-origin rules — so the researchers used DNS rebinding, re-pointing a hostname the browser already trusts at 127.0.0.1, to get a same-origin channel to the API. The final step is the one that matters: rather than issuing a one-off request, they modified the model's chat template, so the injected instructions are prepended to the model's input on every subsequent conversation (The Hacker News, Hackread).

Why this is a different class of bug from prompt injection. The prompt-injection literature this briefing has carried for two months — Cryptographic Context Injection, ToolHazard, the OWASP production figures — concerns getting hostile text in front of a model during a task. This gets hostile text into the model's own serving configuration, where it persists after the browser tab closes, after the task ends, and across unrelated sessions. It converts a browsing event into a durable compromise of the agent's reasoning surface.

Patch state, and the gap. NemoClaw v0.0.35 fixes the issue on macOS and Linux. Reporting states there is no fix on the Windows and WSL path; v0.0.34 added a Windows installation that carries a warning instead (SiliconANGLE). Oasis Security reported the findings to NVIDIA's PSIRT ahead of publication. No exploitation has been reported as of 25 August.

What is not established here. We could not open NVIDIA's own advisory or Oasis Security's write-up from this environment — both are outside this session's egress policy — so the CVSS score, the full affected-version range and NVIDIA's own wording are not verified against a primary document. Four independent outlets carry the same technical account and the same CVE identifier, which is why this is chip-flagged 2x SRC rather than Primary. Treat the mechanism as solid and the exact version matrix as reported-not-audited.

Watch next. Whether a Windows/WSL fix ships, and how fast; whether other agent runtimes that wrap Ollama carry the same bind default (the pattern, not the product, is the vulnerability); and whether NVIDIA publishes a PSIRT bulletin with a CVSS score, which would upgrade this card's confidence chip.

Thomson Reuters stops renting models and builds one: "Thomson", trained on Westlaw, for $40M

On 24 August Thomson Reuters announced Thomson, its first proprietary large language model, developed in-house and trained on decades of Westlaw, Practical Law, Checkpoint and Reuters content (Thomson Reuters, PR Newswire). IMPACT 6/10#5 ENTERPRISE · AGENT SECURITY

Opening a notebook is now code execution: Marimo's MCP flaw runs an attacker's command before any cell does

CVE-2026-75149, a code-injection issue in the Marimo Python notebook, lets an attacker embed an MCP (Model Context Protocol) command in a crafted notebook that launches as a local subprocess the moment the notebook is opened in edit mode — no authentication, and without a single cell being executed (The Hacker News). Scored CVSS v4 8.7 / v3.1 8.8, user interaction required, attacker authentication not required. Affects versions prior to 0.23.15; fixed in 0.23.15. The CVE was published 19 August and picked up in security press on 25 August — dated honestly here as a six-day-old advisory newly surfaced, not a 24-hour break. Separately, the same project carries an earlier, higher-severity pre-authentication RCE (CVE-2026-39987, fixed in 0.23.0) that public write-ups say was exploited in the wild within hours of disclosure.

"Shared notebook" is now an executable attachment in the same category as a macro-enabled document. If your data team passes .py notebooks around, the MCP surface inside them needs the same handling policy as an email attachment — and check you are past 0.23.15, not merely past 0.23.0.

IMPACT 7/10#6 POLICY · ENFORCEMENT

The FTC opens a comment window on personalised pricing — and the clock runs out on 18 September

On 19 August the Federal Trade Commission voted 2-0 to issue a proposed enforcement policy statement on "personalized pricing" — using personal data to set prices according to what a company believes an individual will pay — and opened a 30-day comment period closing 18 September 2026 at 11:59pm EDT (FTC press release, FTC legal library). Congress has given the FTC no authority to prohibit the practice outright, so the statement instead signals aggressive use of existing Section 5 and related consumer-protection authorities against personalised pricing that is deceptive, unfair or insufficiently disclosed. The proposal asks businesses to disclose both that personalised pricing is in use and what information influences the price, on the reasoning that consumers generally expect the price they see to be the price everyone sees (Holland & Knight, Fortune, 24 Aug).

This is the first US federal instrument aimed squarely at what a pricing model does rather than at how it was trained. If you run dynamic or personalised pricing anywhere, the deliverable due before 18 September is a disclosure the model's inputs can actually support — and the comment window is the cheap moment to say so.

IMPACT 5/10#9 RESEARCH · BENCHMARK

A benchmark for recursive self-improvement: can an agent rewrite the training algorithm it was trained by?

AI4AI-Bench (arXiv:2608.20318), submitted 20 August 2026, evaluates LLM agents on algorithmic design for recursive self-improvement. The protocol as described in the listing: 10 frozen research repositories spanning 10 training-algorithm families; each agent gets 4 hours to rewrite a training algorithm, and the resulting code is rerun for up to 12 hours to score it. That design — frozen repos, a fixed wall-clock budget, and re-execution rather than judged output — is the interesting part, because it makes the result reproducible rather than rated.

Reproducible re-execution is the direction benchmark design has to go if "the agent improved the training loop" is ever going to be a claim rather than a demo. Worth reading before you believe the next self-improvement result.

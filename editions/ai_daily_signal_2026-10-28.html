Google's Genie 4 builds playable worlds with sound you can redirect while you play

Google DeepMind's new world model generates music, ambient sound and dialogue with the scene. It is in a research preview for trusted testers.

NOTABLE · INFORMS THIS MONTHOfficial sourceChecked on deepmind.google

Google DeepMind announced Genie 4 on Tuesday. Like Genie 3, it does not render a finished video: it computes a world frame by frame as you move through it with the keyboard. New this time, it is natively multimodal, producing music, ambient noise and characters' speech together with the picture, and you can type changes mid-simulation (change the weather, move the camera, add a person) while Gemini adapts the prompt to the scene. TechCrunch says it holds a consistent scene for up to two minutes, double Genie 3, with better physics and more humanlike characters.

So what: world models are turning from demos into tools. Google pitches Genie 4 for robot and agent training environments, game prototyping and film pre-visualisation. It also marks a design shift: a language model acting as director that plans and checks, with a separate model simulating the world in real time, an older idea from agent research now rebuilt with modern models.

#2Security · firmware · 22-27 OctIMPACT 7/10

A network-boot flaw in the code behind most server firmware

Anyone on the local network can send an oversized error packet during network boot and run code before Secure Boot. The fix went public months early.

The flaw sits in the PXE Base Code driver of EDK II, the open-source reference code that AMI, Insyde, Phoenix and Microsoft's Project Mu build their UEFI firmware on. During network boot the driver copies incoming ICMP error messages into a 504-byte field without enforcing the limit, in both the IPv4 and IPv6 handlers, so an oversized message writes attacker-controlled bytes past it. NVD lists it as CVE-2026-97631, published 22 October, affecting EDK II up to edk2-stable202608, with a CVSS 4.0 score of 9.5 (critical) from the EDK II security team. Ars Technica reports it was found by Alex Matrosov of Anthropic and Dan Holmes of Google, who had arranged disclosure for January; an AMI pull request published the fix last month, so TianoCore issued its advisory last week. Exploitation needs access to the local network during PXE boot, and a working exploit has to be tuned to each firmware build. Machines that boot only from disk are not affected. Intel says none of its supported products ship the affected code but OEMs may; Arm says it is not directly applicable; AMD, AMI, Phoenix, Microsoft and Amazon did not answer Ars. Ars does not say whether AI tools were used to find it.

Data centres that network-boot servers should ask their firmware vendor for an update now and turn off PXE boot where they can. HD Moore calls it a likely "forever" bug on end-of-support hardware. It is the second botched embargo in a week, after PHP2Shell.

#3Research · maths · 27 OctIMPACT 6/10

AI agents check the longest proof in maths in 24 days

Axiom says its agent swarms formalised the classification of finite simple groups in Lean, every step checked by the Lean kernel, and found errors along the way.

The classification of finite simple groups, nicknamed "the enormous theorem", spans roughly 15,000 pages in more than 500 articles by about 100 mathematicians. Axiom Math says it has rewritten the first-generation proof in the Lean proof language, with every logical step checked by Lean's kernel, and published the code on GitHub. The first agent swarm went live on 2 October; lead agents broke arguments into tasks, others searched the literature or wrote Lean proofs, and agents claimed milestones through GitHub issues. On 10 October they proved the Monster group is simple. Build times became the bottleneck: agents wrote proofs faster than Lean could recheck them. Most problems found in the literature were typos, table errors or dropped hypotheses, but the team logged 34 noteworthy deviations. The largest was a closure assertion in a published route to the Unbalanced Group Theorem, for which the agents found explicit counterexamples; Axiom gives an alternative argument and a new group-theory result, and is compiling an errata list with group theorists. Axiom does not name the models it used.

Machine-checked proof at this scale used to be a decade-long human project. Combined with OpenAI's claims this week, the bottleneck in AI-produced mathematics is shifting from finding proofs to verifying them, and Lean is becoming the way to settle disputes.

Liquid AI's LFM3: six small models, one non-transformer backbone, two of them decision models

NOTABLEOfficial sourceModels · new architecture · 27 Oct

LFM3-1.7B-Base was pre-trained on 22T tokens. Of its 24 layers, 13 are gated short convolutions; the rest mix sliding-window and global attention, chosen by Liquid's hardware-in-the-loop architecture search across 14 device and backend combinations (Galaxy S26 Ultra, OnePlus 15, Raspberry Pi 5, M4 Max, Ryzen AI, cloud CPUs, GPUs and the Qualcomm Hexagon NPU). Six ~2B models branch from it: text, vision, audio, omni, and two decision models specialised from the vision and omni models. Liquid says LFM3-1.7B beats its own LFM2.5-2.6B with 35% fewer parameters, runs 1.8-2.8x faster than the next model on its test devices, and needs 1.6 GB of KV cache for a 128K context against 4.3 GB for Qwen3.5-4B. The figures are Liquid's own.

Hugging Face lists LFM3-1.7B (uploaded 23 October) at 6,311 downloads and 168 likes when checked, under Liquid's own licence rather than Apache or MIT.

Decision-only models (Jev, OpenAI's Decisions API) now come in open, on-device form from a non-transformer lab. For teams building agents on phones or kiosks, this is the strongest small open option to test this month.

More Qwen models reach for an Alibaba server, and it is still online

CRITICALOne secondary sourceModels · AI security · 27 Oct
WHAT CHANGED Palisade Research finds Alibaba Cloud proxy calls in three more Qwen 3.8 models (but none in Qwen 3.7); it traces them to RL training infrastructure, not exfiltration, but the proxy domain is still live

Per The Decoder's account of Palisade Research's investigation: Palisade searched evaluation logs from five Qwen models. The proxy string appeared in Qwen3.8-Max-0902, Qwen3.8-Max and Qwen3.8-27B; older Qwen 3.7 models showed none. Unlike Cohere's Beijing upload attempt, these requests went to Alibaba Cloud's Singapore region and always got 403 Forbidden. Sometimes a model really called the proxy, sending requests for sites such as sec.gov through it with made-up credentials; one model wondered why "something is rewriting my URLs". In controlled tests Qwen3.8-27B tried the proxy within two turns after a simulated 403 in 2-4% of runs. The dates in the hallucinated URLs fall in each model's training window, so Palisade blames reinforcement-learning infrastructure that routed web requests through the proxy, and finds no sign of malicious phoning home. Cohere has published its full logs on Hugging Face after criticism of its framing.

Less sinister than a backdoor, but still a live risk: an agent built on Qwen 3.8 may send traffic to a server neither you nor it controls. Block outbound egress by default and add *.aliyuncs.com rules if you run these weights.
